The catalog describes dependency classes, not ownership. Application-specific documentation and research artifacts remain in their canonical repositories.

CI-workflow references in the Execution mode column are verified against each repository's actual public workflow files, not the workload's internal implementation; a repository having CI does not imply its workload itself runs inside that CI. Self-hosted vs hosted labels are inferred from each workflow's declared `runs-on` value where available, and are explicitly marked as inference when that signal is not present. The "interactive" / "batch" local-execution labels are inferred from each repository's stated purpose, not from complete runtime path verification. Treat them as a best-effort estimate until a workload owner confirms or corrects them.

Provenance hooks and CI references marked "Planned" name an artifact that does not exist on `main` yet. `scripts/theseus-report` is already available from #13; this catalog currently treats only `scripts/runner-health.sh` as the remaining missing artifact.
